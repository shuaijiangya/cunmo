# 小程序延后登录与操作鉴权设计

## 目标

小程序启动后直接进入首页，让未登录用户先通过示例数据浏览主要功能。只有当用户执行需要个人数据或写入数据的操作时，才要求微信登录。退出登录后回到访客浏览态，不再次强制弹出登录界面。

## 用户状态

前端区分三种状态：

- `guest`：没有有效登录会话，展示本地示例数据。
- `authenticating`：正在执行微信登录，阻止重复提交。
- `authenticated`：存在有效业务 Token，展示当前用户的真实库存。

登录弹层是否显示与登录状态分离。访客可以主动关闭弹层继续浏览。

## 访客浏览

未登录启动时不请求受保护的库存接口，而是载入固定的本地示例数据。示例数据覆盖：

- 首页的空间、分类、物品和库存数量。
- 透视镜的空间与分类统计。
- 流转轴的库存变化记录。

访客允许执行不改变个人数据的本地交互：

- 切换首页、透视镜和流转轴。
- 切换空间、分类和透视维度。
- 搜索示例物品。
- 浏览示例物品与统计。

示例数据必须显式标记为体验数据，避免用户误认为数据已经保存。

## 受保护操作

以下入口统一通过鉴权守卫：

- 新建空间、分类或物品。
- 调整库存。
- 管理、迁移或删除物品、空间、分类。
- 进入“我的”。
- 其他需要访问当前用户资料或真实库存的操作。

鉴权守卫行为：

1. 已登录时立即执行操作。
2. 未登录时记录一个待继续的用户意图，并显示登录弹层。
3. 用户取消登录时清除待继续意图，停留在当前访客页面。
4. 登录成功后先加载真实库存。新建弹窗和“我的”可继续原操作。
5. 示例物品的增减、管理或删除不能把示例 ID 用于真实库存；此类操作登录后回到真实首页，并提示用户重新选择目标。
6. 同一时刻只保留最近一次待继续意图，避免重复打开弹窗或重复提交。

待继续意图使用可枚举的数据结构表示，例如目标视图或弹窗参数，不在 Pinia 中保存任意函数，保证状态可测试且便于调试。

## 登录和资料

登录继续使用现有 `wx.login -> /api/auth/wechat/login -> Token` 链路。微信身份登录与头像昵称完善保持分离：

- 登录成功即建立业务会话。
- 用户进入“我的”后可通过 `chooseAvatar` 和 `input type="nickname"` 完善资料。
- 未完善头像昵称不阻止使用库存功能，也不在登录后强制跳转“我的”。

登录弹层复用现有 `LoginOverlay.vue`，改为可关闭的弹层，提供：

- 微信登录。
- 暂不登录，继续浏览。
- 稳定的加载、错误和防重复点击状态。

## 退出逻辑

用户在“我的”点击退出时：

1. 弹出确认提示，避免误触。
2. 清除本地 Token、当前用户、个人库存、分页游标、筛选条件和所有业务弹窗。
3. 清除待继续意图和登录错误。
4. 回到首页并立即恢复本地示例数据。
5. 不自动打开登录弹层，用户可继续浏览。

退出只清理本地会话。当前后端没有注销接口，因此本次不新增服务端 Token 注销；后续若增加注销接口，应在清理本地状态前尽力调用，调用失败也必须允许本地退出。

## 401 和会话失效

HTTP 客户端继续在 401 时清除持久化 Token，同时通知前端状态层退出真实数据态。当前操作失败并提示“登录状态已失效，请重新登录”，随后回到访客示例态。为避免突然打断浏览，401 不自动发起微信登录；用户再次执行受保护操作时再显示登录弹层。

## 组件与状态边界

- `inventoryStore`：维护鉴权状态、访客示例数据、待继续意图、真实数据初始化和退出回落。
- `LoginOverlay`：只负责登录交互和取消，不直接决定业务跳转。
- 页面与业务组件：在受保护入口调用明确的鉴权动作，不自行操作 Token。
- `httpClient`：附加 Token、识别 401，并通过可测试的回调同步会话失效。
- 示例数据模块：提供每次可重新创建的固定数据，避免访客操作污染下一次会话。

## 测试

前端单元测试覆盖：

- 无会话启动时进入访客态且不请求库存接口。
- 访客浏览、筛选和搜索只处理本地示例数据。
- 受保护操作打开登录弹层并保存待继续意图。
- 取消登录清除待继续意图。
- 登录成功加载真实数据并继续原操作。
- 已登录时受保护操作直接执行。
- 未完善资料不会被强制跳转。
- 退出确认后清理会话、恢复示例数据并回到首页。
- 401 清理前端会话并恢复访客态。

构建验证包括 Vitest、TypeScript 检查和微信小程序构建。
