# 存魔库存删除与转移设计

## 1. 目标

为库存空间、分类和物品增加安全删除能力，并在存在下级数据时提供：

- 批量转移后删除；
- 清零库存并删除；
- 分类从当前空间解绑；
- 分类全局删除。

所有操作必须满足魔方域数据隔离、容量限制、事务一致性和流水可追溯要求。

## 2. 核心原则

1. 空间、分类、物品使用逻辑删除，不物理删除业务主记录。
2. 空间分类绑定属于关系数据，完成业务校验后可以物理删除。
3. 库存流转流水永久保留，不随空间、分类或物品删除。
4. 删除、转移、绑定补充和流水写入必须处于同一数据库事务。
5. 默认空间和默认分类与用户创建数据遵循相同规则，均允许删除。
6. 首期不提供回收站和用户端恢复能力。
7. 删除预览只提供决策信息，执行接口必须重新加锁并校验，不能信任预览结果。

## 3. 删除策略

统一定义两种执行策略：

```text
MOVE          转移依赖数据后删除或解绑
CLEAR_DELETE  清零并删除依赖物品后删除或解绑
```

## 4. 删除物品

物品是结构树的叶子节点，删除时不提供迁移策略。用户查看影响预览后直接确认删除：

- 记录删除前库存数量；
- 将库存清零并逻辑删除物品；
- 写入 `DELETE` 流水；
- 流水的数量变化为负的原库存数量；
- 删除前的物品、空间、分类和精准位置使用快照保存。

## 5. 删除空间

### 5.1 删除预览

返回：

- 空间基本信息；
- 绑定分类数量；
- 有效物品种类数；
- 当前库存总件数；
- 可选目标空间；
- MOVE 策略的容量影响；
- 是否允许直接删除。

### 5.2 空空间

空间没有有效物品时：

- 删除该空间的全部分类绑定；
- 逻辑删除空间；
- 仍绑定其他空间的分类继续保留；
- 不再绑定任何空间且没有有效物品的分类同步逻辑删除，避免产生不可见孤立分类。

### 5.3 转移后删除

用户统一选择一个目标空间：

1. 锁定源空间、目标空间和相关物品。
2. 按分类统计待转移物品种类数。
3. 目标空间缺少原分类绑定时自动创建绑定。
4. 按目标空间和分类组合执行容量校验。
5. 将源空间全部有效物品批量移动到目标空间。
6. 所有物品精准位置改为“待整理”。
7. 每个物品写入一条 `MOVE` 流水。
8. 删除源空间全部分类绑定。
9. 逻辑删除不再绑定任何空间且没有有效物品的孤立分类。
10. 逻辑删除源空间。

源空间和目标空间不能相同。任何组合容量不足时，整批操作失败并回滚。

### 5.4 清零并删除

1. 锁定源空间和全部有效物品。
2. 每个物品按删除前库存写入 `DELETE` 流水。
3. 将全部物品库存清零并逻辑删除。
4. 删除源空间全部分类绑定。
5. 逻辑删除不再绑定任何空间且没有有效物品的孤立分类。
6. 逻辑删除空间。

不允许部分成功。

## 6. 分类解绑

分类解绑只影响指定的“空间 + 分类”组合，不删除分类主记录。

### 6.1 当前组合没有物品

- 直接删除空间分类绑定；
- 分类在其他空间继续可用。

### 6.2 转移后解绑

用户选择当前空间内的一个目标分类：

1. 目标分类必须已绑定当前空间。
2. 源分类和目标分类不能相同。
3. 按当前空间和目标分类组合校验容量。
4. 将源组合内全部物品改为目标分类。
5. 精准位置改为“待整理”。
6. 每个物品写入 `MOVE` 流水。
7. 删除源空间分类绑定。

### 6.3 清零并解绑

1. 对源组合内每个物品写入 `DELETE` 流水。
2. 清零并逻辑删除这些物品。
3. 删除源空间分类绑定。
4. 分类主记录及其他空间绑定保持不变。

## 7. 全局删除分类

### 7.1 删除预览

返回：

- 分类基本信息；
- 已绑定空间列表；
- 各空间下物品种类数和库存总件数；
- 可选目标分类；
- MOVE 策略在各空间下的容量影响。

### 7.2 没有物品

- 删除分类的全部空间绑定；
- 逻辑删除分类。

### 7.3 转移后删除

用户统一选择一个目标分类：

1. 目标分类必须属于当前魔方域且不能是源分类。
2. 获取源分类涉及的全部空间。
3. 目标分类未绑定相关空间时自动创建绑定。
4. 分别按每个“空间 + 目标分类”组合校验容量。
5. 将源分类全部有效物品批量修改为目标分类。
6. 精准位置改为“待整理”。
7. 每个物品写入 `MOVE` 流水。
8. 删除源分类全部绑定。
9. 逻辑删除源分类。

任一空间容量不足时整批回滚。

### 7.4 清零并删除

- 清零并逻辑删除源分类下全部有效物品；
- 每个物品写入 `DELETE` 流水；
- 删除源分类全部绑定；
- 逻辑删除源分类。

## 8. 容量计算

容量限制针对有效物品种类数，不是库存件数：

```text
目标组合现有有效物品数 + 本次迁入物品数 <= item_limit_per_space_category
```

计算时：

- 排除本次操作中已经位于目标组合的物品；
- 不合并同名物品，每个物品主键仍算一个种类；
- 容量为 `NULL` 时跳过限制；
- 校验与更新必须在锁定魔方域后执行，避免并发越限。

失败错误码：

```text
TARGET_CAPACITY_EXCEEDED
```

响应应包含发生超限的目标空间名称、分类名称、当前数量、迁入数量和上限。

## 9. 流转流水

### 9.1 类型扩展

```text
IN
OUT
WARN
MOVE
DELETE
```

### 9.2 快照字段

在现有流水表增加：

```text
source_space_snapshot
source_category_snapshot
source_detail_location_snapshot
target_space_snapshot
target_category_snapshot
target_detail_location_snapshot
```

规则：

- `MOVE` 同时记录来源和目标快照；
- `DELETE` 记录来源快照，目标快照为空；
- `DELETE.quantity_delta` 等于负的删除前库存；
- 库存为零的删除流水 `quantity_delta=0`；
- 删除空间和分类时按物品记录流水，不额外伪造库存数量流水。

流水说明示例：

```text
MOVE:    因删除空间“办公室”，物品已转移
DELETE:  因全局删除分类“电子数码”，库存清零并删除
```

## 10. 数据库处理

不增加外键。

需要新增迁移脚本，为 `inv_stock_transaction` 增加来源和目标快照字段，并扩展
`transaction_type` 的字段注释。

空间、分类和物品继续使用现有：

```text
status
version
deleted
```

批量物品转移和删除必须带 `vault_id`、`deleted=0` 和版本条件，出现并发冲突时
整批回滚。

## 11. DDD 边界

### 11.1 领域层

新增：

- `DeletionStrategy`
- `InventoryMove`
- 删除与转移规则方法
- 容量计算领域规则

领域层只表达规则，不依赖 MyBatis、Spring 或 HTTP。

### 11.2 应用层

新增用例：

- 查询删除预览；
- 移动物品；
- 删除物品；
- 删除空间；
- 解绑分类；
- 全局删除分类。

应用服务负责事务编排、锁定顺序和调用仓储。

### 11.3 基础设施层

仓储负责：

- 查询并锁定源对象和目标对象；
- 批量修改空间或分类；
- 批量逻辑删除；
- 差量维护分类绑定；
- 写入不可变流水。

读模型负责删除预览，不直接执行删除。

## 12. HTTP 接口

### 12.1 空间

```text
GET  /api/inventory/spaces/{spaceId}/deletion-preview
POST /api/inventory/spaces/{spaceId}/deletion
```

MOVE 请求：

```json
{
  "strategy": "MOVE",
  "targetSpaceId": 12
}
```

CLEAR_DELETE 请求：

```json
{
  "strategy": "CLEAR_DELETE"
}
```

### 12.2 分类

```text
GET  /api/inventory/categories/{categoryId}/deletion-preview
POST /api/inventory/categories/{categoryId}/unbinding
POST /api/inventory/categories/{categoryId}/deletion
```

解绑请求：

```json
{
  "spaceId": 11,
  "strategy": "MOVE",
  "targetCategoryId": 25
}
```

全局删除请求：

```json
{
  "strategy": "MOVE",
  "targetCategoryId": 25
}
```

### 12.3 物品

```text
GET  /api/inventory/items/{itemId}/deletion-preview
POST /api/inventory/items/{itemId}/deletion
```

删除接口不需要请求体。

## 13. 错误码

```text
SPACE_NOT_FOUND
CATEGORY_NOT_FOUND
ITEM_NOT_FOUND
TARGET_SPACE_NOT_FOUND
TARGET_CATEGORY_NOT_FOUND
SAME_SOURCE_AND_TARGET
TARGET_CATEGORY_NOT_BOUND
TARGET_CAPACITY_EXCEEDED
DELETE_CONFLICT
INVENTORY_CONFLICT
INVALID_DELETE_STRATEGY
```

所有错误都必须转换为稳定 HTTP 响应，不能向前端返回数据库异常。

## 14. 前端交互

### 14.1 入口

- 空间和分类导航项通过长按或管理菜单打开操作面板；
- 物品卡片增加管理菜单；
- 删除使用文字明确的危险操作，不只使用无说明图标。

### 14.2 删除弹窗

流程分两步：

1. 请求删除预览并展示影响范围；
2. 用户选择转移或清零删除，并完成目标选择。

确认按钮文案必须显示影响数量，例如：

```text
转移 8 个物品并删除空间
清零 36 件库存并删除
```

清零删除使用红色危险按钮，并要求再次确认。提交期间禁止关闭和重复提交。

### 14.3 执行完成

- 刷新 bootstrap、物品列表、透视镜和流转轴；
- 当前筛选对象被删除时切换到“全部”；
- 分类解绑后若当前正在查看该组合，分类筛选切换为“全部分类”；
- 后端冲突时保留弹窗并重新加载删除预览。

## 15. 测试要求

### 15.1 领域测试

- 库存大于零不能直接无策略删除；
- MOVE 不改变库存数量；
- CLEAR_DELETE 生成正确负数变化量；
- 有限容量批量迁入超限；
- 无限容量允许批量迁入。

### 15.2 应用与仓储测试

- 删除空空间；
- 空间转移时自动补充分类绑定；
- 空间清零删除全部物品；
- 当前空间分类解绑不影响其他空间；
- 全局分类删除处理全部绑定；
- 任一迁移组合失败时事务整体回滚；
- 并发版本冲突时不产生部分流水。

### 15.3 前端测试

- 删除预览正确展示影响数量；
- MOVE 策略必须选择有效目标；
- CLEAR_DELETE 必须二次确认；
- 删除当前筛选对象后重置筛选；
- 成功后刷新四类服务端状态；
- 失败后保留弹窗并显示稳定错误信息。

## 16. 不在首期范围

- 回收站和恢复；
- 定时清理逻辑删除数据；
- 多目标分配或逐个物品选择目标；
- 同名物品自动合并；
- 删除审批流；
- 管理后台批量恢复。
