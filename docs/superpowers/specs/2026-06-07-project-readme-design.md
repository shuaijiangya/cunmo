# 存魔项目 README 设计

## 1. 目标

在项目根目录新增 `README.md`，同时服务两类读者：

- 第一次接手项目的开发者，可以理解项目用途、目录结构并完成本地启动。
- 参与技术评审的开发者，可以理解 Java 架构的设计理由、当前不足和后续演进方向。

`backend/README.md` 保留为 Java 后端专项说明，根 README 提供全局入口并链接到它。

## 2. 内容结构

README 按“先使用、后解释”的顺序组织：

1. 项目定位与当前能力。
2. 技术栈与目录结构。
3. 前后端、本地数据库的快速启动与验证命令。
4. 系统调用链和 Java 六模块职责。
5. 关键设计决策及其原因。
6. Java 当前存在的问题、形成原因、风险和建议方向。
7. 开发约束、数据库脚本顺序和设计文档索引。

## 3. 事实边界

README 只描述仓库中已经存在或设计文档已经明确约束的能力，不把规划写成已实现。

需要明确区分：

- 已实现：微信登录、资料更新、库存管理、统计、流水、结构删除和迁移。
- 有意设计：DDD 模块化单体、读写模型分离、`vault_id` 数据隔离、无数据库外键、逻辑删除、流水快照。
- 当前不足：细粒度 RBAC 尚未执行、Sa-Token 登录态尚未接入共享存储、头像仍使用本地磁盘、SQL 迁移依赖人工执行、测试覆盖不均、部分模块边界存在反向耦合和大类问题。

问题说明采用“现状、原因、影响、建议”的结构，避免只列缺点或脱离当前阶段批评设计。

## 4. 表达原则

- 使用中文。
- 命令必须可以从仓库现有脚本、POM 和配置中得到验证。
- 架构图使用 Mermaid，确保 Markdown 阅读时仍有文字说明。
- 不包含真实密钥、数据库密码或用户标识。
- 不修改用户当前未提交的 Java 配置和测试文件。

## 5. 验收标准

1. 根目录存在完整 `README.md`。
2. 新开发者可以据此配置前端、MySQL 和 Java 服务。
3. Java 模块依赖、运行时调用链和数据库脚本顺序与代码一致。
4. 设计理由包含收益、代价和适用阶段。
5. Java 问题列表均能从当前仓库找到事实依据。
6. Markdown 无占位符、无失效的仓库内相对链接。
